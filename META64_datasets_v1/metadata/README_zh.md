## 2. 怎样实现均衡抽样

把 [0.1,0.5] 分成十个宽度 0.04 的档位，左闭右开、最后一档包含 0.5：

| 清单 | 每档数量 | 合计 |
| --- | ---: | ---: |
| train3000 | 300 | 3,000 |
| train1000 | 100 | 1,000 |
| valid300 | 30 | 300 |
| valid100 | 10 | 100 |
| 每类 test300 | 30 | 300 |

训练、验证、ID 和 CR 的档内抽样按受约束节点数（2、3、4+）与受载节点数（1、2、3+）联合分层，按候选池实际比例用最大余数法分配名额，再按固定种子无放回抽取。

OOD 的线段工况不能直接解释成同样的点支承／点载荷类别，因此首轮 OOD 仅强制体积分数每档 30 个，档内随机抽取；不按成绩或是否有固定自由度载荷筛选。

官方全量三套测试各 1,000 个保持原始分布，不强制每档相等。完整、首轮的实际分布见 `audits/distributions.json`。

## 3. 训练、验证与官方测试如何隔离

本次读取全部 33,100 个官方任务的载荷和约束，建立规范化物理组索引，再选择训练和验证。

组键规则：

- 物理域统一为 64×64；把 64 和 256 网格的节点映射到同一 256 整数坐标格，比较物理位置，而非原数组编号。
- 支承保留 x/y 约束类型。
- 载荷用整体 L2 范数归一化，保留多个载荷的相对大小；比较整体符号反转。
- 比较正方形的八种轴交换／镜像变换，并正确变换力方向和约束分量。
- 规范化力分量舍入到 10 位小数，取规范表示的 SHA-256。
- 体积分数不进入组键，同一边界载荷的不同材料预算变体不跨训练／验证／测试。
- 对零位移约束，固定自由度上的外力只在“组比较”时排除；复制的原始 forces 数组没有修改。

在此明确规则下，训练与验证、训练与全部官方测试、验证与全部官方测试的组交集均为 **0**。首轮集合嵌套于各自完整集合，因此继承这些隔离关系。

这是声明的规范化等价判断，不是对任意近似相似工况、任意物理问题的绝对无重复证明。当前规则适用于本数据的各向同性线弹性、零位移约束和柔顺度实验。细节与排除列表见 `audits/group_disjointness.json`。

## 6. 如何读首轮数据

```python
from pathlib import Path
import json
import numpy as np

root = Path('/public/home/cairn/topo/InitSkill-Lab/data/META64_stratified_3000_v1')
with (root / 'manifests/train1000.jsonl').open() as f:
    task = json.loads(next(f))

arrays = {
    field: np.load(root / asset['path'], allow_pickle=False)
    for field, asset in task['assets'].items()
}
print(task['task_key'], task['source_key'], task['group_id'])
print(arrays['forces'].shape, arrays['normals'].shape)
print(float(arrays['target_vf']))
```

首轮运行分别读取 `train1000`、`valid100`、三类 `test_*300` 清单；完整运行读取相应完整清单。不要直接遍历 `raw/train/` 来代表首轮 1,000，也不要把六个数组当成六个独立任务。

## 7. 与 InitSkill-Lab 求解器的接口边界

本次完成的是**原始数组抽样、隔离、复制与清单准备**，没有把全部任务转换成 `initskill-isotropic-task-v1` 的 `task.json/domain.npz/boundary_conditions.npz` 目录，也没有自动改变现有实验队列。

转换时需要核对作者 `[x,y,dof]` 轴约定与项目节点顺序。参考柔顺度是均匀设计 FE 值，不能直接当作 Uniform50 等优化终点基线；应变能字段已经过对数归一化。

- OOD 全集保留原来的 25 个固定自由度带载荷任务；首轮 300 中实际包含 8 个，没有按此特征删样本。当前求解器会拒绝这类输入，后续需要显式审计自由／约束自由度载荷处理，不能静默改原始 forces。
- CR 保留 256×256 原网格和物理域 64×64，单元尺寸为 0.25；普通任务单元尺寸为 1。不得未经核对把 CR 当成物理尺寸 256×256，或把它静默缩到 64×64。
- 任何过滤、物理场参考 FE 和额外初始化计算都应统一规则并计入预算；本次没有执行 FE 或优化。

因此，“数据已准备”不等于全部集合已直接适配现有求解入口。现有求解器与历史 META64 小子集未修改。

## 8. 复现与核验

抽样程序位于 `scripts/public_datasets/prepare_stratified_meta.py`。程序保留源物理组审计身份，使用文件锁避免重复写入；已完成的数据目录不会自动覆盖。

各选择种子记录在 `manifest.json` 与 `selection.json`。分布、嵌套关系、组隔离、材料化文件数和目标文件抽查分别保存在审计文件中。原始六字段逐文件记录源字节的 SHA-256，并检查写入长度；首、中、末任务的目标文件另做哈希抽查。

本划分是自建均衡子集，不能写成论文原始 3,000 任务。固定官方测试与性能评价结果需与原作者数据求解设置区别说明。
